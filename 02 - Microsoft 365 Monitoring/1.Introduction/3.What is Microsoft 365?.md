
Microsoft 365 (M365) is a collection of cloud-based productivity and collaboration services tied to Entra ID identities. Once a user authenticates through Entra ID, they gain access to services like:

- **Exchange Online (Outlook):** Email, calendars, and mailbox management
- **SharePoint Online:** Document storage, file sharing, and team sites.
- **OneDrive:** Personal cloud storage.
- **Teams:** Chat, meetings, and collaboration.
- **Other services:** Power BI, Dynamics, and various Microsoft apps.

The key distinction is:

> **Entra ID tells you about identity and authentication. M365 tells you about activity performed using that identity.**

## 1. Entra ID vs Microsoft 365

Think of the environment like this:

```text
                 ATTACKER
                    │
                    ▼
              ┌───────────┐
              │ Entra ID  │
              └─────┬─────┘
                    │
              Authentication
                    │
                    ▼
              ┌───────────┐
              │ Microsoft │
              │    365    │
              └─────┬─────┘
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
    Outlook     SharePoint    OneDrive
       │
       ▼
     Teams
```

So if you discover:

> `john.doe@example.com` successfully authenticated from a suspicious IP

Entra ID answers:

**“Did John authenticate?”**

But the next question is:

> **“What did whoever controlled John's account actually do?”**

That's where M365 logs become valuable.

---

# 2. Why M365 is such a juicy target

An attacker doesn't necessarily want the account itself.

They want what's **behind the account**.

A compromised employee account could potentially provide access to:

### Email

Potentially contains:

- Business discussions
    
- Financial information
    
- Passwords accidentally shared through email
    
- Customer information
    
- Internal documents
    
- Security notifications
    
- Password-reset messages
    

### SharePoint

Potentially contains:

- Corporate documents
    
- Source code
    
- Policies
    
- Customer information
    
- Strategic plans
    
- Internal procedures
    

### OneDrive

Personal/team files associated with the user.

### Teams

Potentially exposes:

- Internal conversations
    
- Files
    
- Meeting information
    
- Organizational relationships
    

So the attack chain can become:

```text
Stolen credentials
       ↓
Entra ID authentication
       ↓
Compromised account
       ↓
M365 access
       ↓
Email / Files / Teams
       ↓
Sensitive information
```

---

# 3. The important concept: Valid Access

This is where cloud attacks become tricky.

Suppose the attacker uses:

```text
john.doe@example.com
```

with legitimate authentication.

The system may see:

> **Valid user**

The attacker doesn't necessarily look like malware.

They're potentially operating **as the user**.

Therefore:

> **Authentication success does not mean activity is legitimate.**

This is one of the most important SOC lessons in cloud security.

---

# 4. Unified Audit Log

M365 activity is collected through the **Unified Audit Log**.

Conceptually:

```text
                  Unified Audit Log
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
    Exchange         SharePoint        OneDrive
        │                │                │
        ▼                ▼                ▼
      Email            Files            Files
                         │
                         ▼
                       Teams
```

This gives investigators a centralized place to investigate user and administrative activity across M365 services.

---

# 5. Exchange logs — extremely important

If an attacker compromises an email account, don't just ask:

> “Did they read emails?”

Look for the **entire mailbox attack pattern**.

Important activities include:

### Email access

Potentially:

> Attacker reading sensitive messages.

### Email sending

Potentially:

> Attacker sending phishing or fraudulent messages from a legitimate account.

### Email deletion

This can be particularly interesting.

An attacker may delete security notifications or evidence.

### Mailbox rules

This deserves special attention.

For example:

```text
Incoming Email
      │
      ▼
Mailbox Rule
      │
      ├── Move message
      ├── Delete message
      └── Forward message
```

An attacker could abuse rules to manipulate or redirect email.

---

# 6. Forwarding rules

Suppose the attacker creates a forwarding mechanism:

```text
Victim Mailbox
      │
      ▼
Forwarding Rule
      │
      ▼
External Destination
```

Now future emails may be exposed without the attacker needing to repeatedly log into the mailbox.

From an investigation perspective, that's potentially significant **persistence or collection behavior**.

So after account compromise, ask:

> **Did the attacker modify mailbox rules or forwarding settings?**

---

# 7. SharePoint and OneDrive

Now move from communication to **data access**.

Interesting activities include:

- File access
    
- File downloads
    
- File modification
    
- File sharing
    
- Permission changes
    
- Folder operations
    

Imagine:

```text
10:00  Suspicious login
10:05  SharePoint accessed
10:07  Finance folder accessed
10:08  200 files downloaded
10:15  External sharing configured
```

That is much more concerning than simply:

> “User logged in.”

You now have evidence of potential **data collection/exfiltration**.

---

# 8. Application permissions

This is another area you should pay attention to.

An attacker may attempt to grant permissions to an application.

Conceptually:

```text
Compromised Identity
        │
        ▼
Grant Application Permission
        │
        ▼
Application gets access
        │
        ▼
Potential continuing access
```

This is important because application-based access can behave differently from a normal interactive user login.

For SOC investigations, don't only look for:

> Human → Resource

Also consider:

> **Application → Resource**

That's why workload/application identities matter from your earlier lesson.

---

# 9. How to connect the logs

This is the real skill.

Suppose Entra ID shows:

```text
09:00
John authenticates

IP: 203.0.113.45
Device: Unknown
```

Now M365 shows:

```text
09:03  Outlook accessed
09:05  Sensitive email accessed
09:08  Mailbox rule created
09:12  SharePoint accessed
09:15  Files downloaded
```

You can now build a narrative:

> **A suspicious authentication occurred, followed by mailbox access, persistence-related mailbox changes, and access to corporate files.**

That is an actual incident story.

---

# 10. The timeline is everything

Don't investigate each log independently.

Build a timeline:

|Time|Source|Activity|Interpretation|
|---|---|---|---|
|09:00|Entra ID|Successful login|Possible initial access|
|09:02|Entra ID|MFA successful|Authentication completed|
|09:04|Exchange|Mailbox accessed|Post-auth activity|
|09:07|Exchange|Rule created|Possible persistence|
|09:10|SharePoint|Files accessed|Collection|
|09:15|OneDrive|Files downloaded|Possible exfiltration|
|09:20|Exchange|Emails sent|Possible abuse|

Now you're thinking like an analyst rather than a log-searching robot. 😄

# 11. A useful investigation model

For cloud identity incidents, use this:

```text
IDENTITY
   │
   ▼
AUTHENTICATION
   │
   ▼
ACCESS
   │
   ▼
ACTIVITY
   │
   ▼
PERSISTENCE
   │
   ▼
COLLECTION
   │
   ▼
EXFILTRATION / IMPACT
```

Map the logs:

```text
Entra ID
   │
   └── Authentication

Audit Logs
   │
   └── Identity/configuration changes

M365 Logs
   │
   ├── Email
   ├── Files
   ├── Teams
   └── Applications
```

---

# 12. What I'd remember for SOC interviews

If asked:

**“What would you investigate after confirming an Entra ID account compromise?”**

A strong answer:

> “I would investigate Microsoft 365 activity associated with the compromised identity. I would review Exchange activity for mailbox access, email operations, mailbox rules, forwarding rules and permission changes. I would review SharePoint and OneDrive for file access, downloads, modifications and sharing changes. I would also investigate application permission grants and administrative actions. Finally, I would correlate these events with Entra ID sign-in and audit logs to build a timeline and determine whether the attacker performed persistence, data collection, exfiltration, or other malicious activity.”

That's a solid answer because you're showing **correlation**, not just listing logs.

## The cheat sheet

|Layer|Main question|
|---|---|
|**Entra Sign-in**|How did they authenticate?|
|**Entra Audit**|What identity/configuration changes occurred?|
|**Exchange**|What happened to the mailbox?|
|**SharePoint**|What corporate files were accessed?|
|**OneDrive**|What files were accessed/downloaded?|
|**Teams**|What collaboration activity occurred?|
|**Application activity**|Did an app receive new permissions?|

### The golden chain

**Entra ID → Who got in**

**Audit Logs → What changed**

**M365 Logs → What they did**

**Timeline → What actually happened**

And that's the progression you want burned into your brain for SOC investigations.
