# 2. Entra ID — Sign-in Logs

### List all Sign-in events

```spl
index="scenario" sourcetype="azure:aad:signin"
```

**Purpose:** Start authentication investigation.

---

### List failed Sign-ins

```spl
index="scenario" sourcetype="azure:aad:signin" "status.errorCode"!=0
```

**Purpose:** Find failed authentication attempts.

---

### Summarize failed Sign-ins by user

```spl
index="scenario" sourcetype="azure:aad:signin" "status.errorCode"!=0
| stats count as event_count values(ipAddress) as ip_addresses
  values(appDisplayName) as applications
  values(status.errorCode) as errorCodes
  by userPrincipalName
| sort - event_count
| table applications, userPrincipalName, ip_addresses, errorCodes, event_count
```

### What this tells you

```text
User
 ├── Number of failures
 ├── Source IP(s)
 ├── Application(s)
 └── Error code(s)
```

This is excellent for identifying **password attacks / suspicious authentication patterns**.

---

# 3. Common Entra Sign-in Error Codes

|Error code|Meaning|
|---|---|
|`0`|Successful authentication|
|`50126`|Invalid username/password|
|`50053`|Account locked due to too many failures|
|`50074`|MFA required but not provided|
|`50055`|Password expired|

### Quick logic

```text
errorCode = 0
     ↓
SUCCESS

errorCode != 0
     ↓
FAILURE
```

# 4. Pivot From Suspicious IP → Successful Logins

Once you identify a suspicious IP:

```spl
index="scenario" sourcetype="azure:aad:signin"
"status.errorCode"=0
ipAddress="<ADD-IP-HERE>"
| stats values(ipAddress) as ip_addresses
  values(appDisplayName) as applications
  by userPrincipalName
| table applications, userPrincipalName, ip_addresses
```

### Investigation question

> **Which accounts successfully authenticated from this suspicious IP?**

This is one of your most important pivot queries.

# 6. Audit — Changes Targeting a Specific User

```spl
index="scenario" sourcetype="azure:aad:audit"
targetResources{}.userPrincipalName="<ADD-USER-EMAIL>"
| eval initiator=coalesce(
    'initiatedBy.user.userPrincipalName',
    'initiatedBy.app.displayName'
)
| sort - _time
| table _time, initiator, activityDisplayName, result,
        targetResources{}.userPrincipalName
```

### Question answered

> **What happened to the compromised account?**

Look for:

- Password changes
    
- Authentication-method changes
    
- Group membership changes
    
- Role assignments
    
- User modifications
    
- Application-related changes
    

---

# 7. Audit — Actions Performed BY a User

```spl
index="scenario" sourcetype="azure:aad:audit"
initiatedBy.user.userPrincipalName="<ADD-USER-EMAIL>"
| sort - _time
| table _time,
        initiatedBy.user.userPrincipalName,
        activityDisplayName,
        result,
        targetResources{}.userPrincipalName
```

### Question answered

> **What did this account do?**

This is different from the previous query.

### Remember

```text
targetResources
      ↓
What happened TO the user?

initiatedBy
      ↓
What did the user DO?
```

# 9. M365 — Investigate a Specific Compromised User

```spl
index="scenario" sourcetype="o365:management:activity"
UserId="<ADD-USER-EMAIL>"
| sort - _time
| eval sourceIP=coalesce('ClientIP', 'ClientIPAddress')
| table _time, Operation, UserId, sourceIP, Workload, ObjectId
```

### This gives you

```text
_time
Operation
UserId
sourceIP
Workload
ObjectId
```

In plain English:

> **When did the user do what, from where, against what resource, in which M365 service?**

---

# 10. M365 Important Fields

|Field|Meaning|
|---|---|
|`_time`|When|
|`Operation`|What happened|
|`UserId`|Who performed it|
|`ClientIP`|Source IP|
|`ClientIPAddress`|Alternative source IP field|
|`sourceIP`|Normalized IP created with `coalesce()`|
|`Workload`|M365 service|
|`ObjectId`|Target resource|

---

# 11. `coalesce()` Cheat

```spl
| eval sourceIP=coalesce('ClientIP', 'ClientIPAddress')
```

Meaning:

> Use `ClientIP` if available; otherwise use `ClientIPAddress`.

This is useful for normalizing inconsistent field names.

# 12. High-Value M365 Operations to Hunt

### Exchange / Mailbox

Look for:

```text
New-InboxRule
Send
Delete
Move
```

Potential concerns:

- Malicious inbox rules
    
- Email forwarding
    
- Security-email deletion
    
- Mass email activity
    
- Phishing from compromised account
    

---

### SharePoint / OneDrive

Look for operations involving:

```text
FileAccessed
FileDownloaded
FileModified
```

Potential concerns:

- Mass file access
    
- Large-scale downloads
    
- Sensitive document access
    
- External sharing
    
- Unusual file activity

# 14. Search M365 Activity From a Suspicious IP

Once you have an attacker IP:

```spl
index="scenario" sourcetype="o365:management:activity"
"ClientIP"="<ADD-IP-HERE>"
```

If the dataset uses the alternative field:

```spl
index="scenario" sourcetype="o365:management:activity"
"ClientIPAddress"="<ADD-IP-HERE>"
```

Or normalize both:

```spl
index="scenario" sourcetype="o365:management:activity"
| eval sourceIP=coalesce('ClientIP', 'ClientIPAddress')
| search sourceIP="<ADD-IP-HERE>"
| table _time, Operation, UserId, sourceIP, Workload, ObjectId
```

This lets you pivot:

> **Suspicious IP → M365 activity**

# 16. Sort Chronologically

### Newest first

```spl
| sort - _time
```

### Oldest first

```spl
| sort _time
```

For incident investigation, newest-first is useful for reviewing recent activity, while oldest-first is often better when **building the attack timeline**.

# 20. The “6 Questions” Method

Whenever you investigate any event, force yourself to answer:

|Question|Field|
|---|---|
|**Who?**|`UserId` / `userPrincipalName`|
|**When?**|`_time` / `createdDateTime`|
|**Where?**|`ipAddress` / `ClientIP`|
|**What?**|`Operation` / `activityDisplayName`|
|**Which service?**|`Workload` / `appDisplayName`|
|**What resource?**|`ObjectId` / `targetResources`|

If you can answer those six, you're no longer just looking at logs—you are **reconstructing the incident**.
