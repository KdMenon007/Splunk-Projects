
# 0. Core Investigation Model

```text
                    ENTRA ID ATTACK
                          │
                          ▼
                 SIGN-IN LOGS
                          │
              ┌───────────┴───────────┐
              ▼                       ▼
        Failed Sign-ins        Successful Sign-in
              │                       │
       ┌──────┴──────┐                ▼
       ▼             ▼           MFA / Risk
 Password Spray   Brute Force         │
                                     ▼
                              Conditional Access
                                     │
                                     ▼
                              AUDIT LOGS
                                     │
                  ┌──────────────────┼─────────────────┐
                  ▼                  ▼                 ▼
              New User           Role Change       MFA Change
                  │                  │                 │
                  └──────────────────┼─────────────────┘
                                     ▼
                              OAuth Consent
                                     │
                                     ▼
                                Persistence
```

### The four questions

For every investigation, ask:

> **WHO?** → `userPrincipalName`, `initiatedBy`

> **FROM WHERE?** → `ipAddress`, `location.countryOrRegion`

> **WHAT HAPPENED?** → `status.errorCode`, `activityDisplayName`, `riskDetail`

> **WHAT CHANGED?** → `targetResources`, role/MFA/OAuth details

# 1. Failed Sign-in Base Filter

### Purpose

Starting point for failed Entra ID authentication events.

```spl
index="task-2" sourcetype="azure:aad:signin" "status.errorCode"!=0 conditionalAccessStatus!=success
```

### Key fields

```text
_time
userPrincipalName
ipAddress
location.countryOrRegion
status.errorCode
status.failureReason
appDisplayName
```

### Remember

```text
status.errorCode != 0
        ↓
Failed authentication

conditionalAccessStatus != success
        ↓
Remove successful Conditional Access evaluations
```

# 2. Password Spraying Detection

### Purpose

Find an IP attacking **many different accounts**.

```spl
index="task-2" sourcetype="azure:aad:signin" "status.errorCode"!=0 conditionalAccessStatus!=success
| stats dc(userPrincipalName) as targeted_accounts, count as failures by ipAddress
| sort - failures
```

### Key concept

```text
ONE IP
  ↓
MANY USERS
  ↓
MANY FAILURES
  ↓
PASSWORD SPRAY
```

### Important Splunk function

```spl
dc(userPrincipalName)
```

`dc` = **distinct count**.

### What to investigate

|Field|Question|
|---|---|
|`ipAddress`|Who is attacking?|
|`targeted_accounts`|How many users?|
|`failures`|How many attempts?|

# 3. Throttled Brute Force Detection

### Purpose

Find repeated authentication failures against a **single user**.

```spl
index="task-2" sourcetype="azure:aad:signin" "status.errorCode"!=0 conditionalAccessStatus!=success
| stats count as failures, dc(userPrincipalName) as targeted_accounts by ipAddress, userPrincipalName
| sort - failures
```

### Pattern

```text
ONE IP
  ↓
ONE USER
  ↓
MANY FAILURES
  ↓
THROTTLED BRUTE FORCE
```

### Difference

|Password Spray|Brute Force|
|---|---|
|Many accounts|One account|
|Distributed|Concentrated|
|`targeted_accounts` high|Usually `1`|
|Few passwords across users|Many attempts against one user|

# 5. Conditional Access Policy Failures

### Purpose

Identify which Conditional Access policies failed/blocked sign-ins.

```spl
index="task-3" sourcetype="azure:aad:signin" conditionalAccessStatus=failure
| spath output=policies path=appliedConditionalAccessPolicies{}
| mvexpand policies
| spath input=policies output=policy_result path=result
| spath input=policies output=policy_name path=displayName
| where policy_result="failure"
| stats values(policy_name) as FailedPolicies by _time, appDisplayName, userDisplayName, ipAddress, conditionalAccessStatus
| eval FailedPolicies=mvjoin(FailedPolicies, ", ")
| table _time, appDisplayName, userDisplayName, ipAddress, conditionalAccessStatus, FailedPolicies
| sort - _time
```

### Query flow

```text
Sign-in
   ↓
Extract CAP policies
   ↓
Expand policies
   ↓
Extract result/name
   ↓
Keep failures
   ↓
Show failed policy
```

### Important

```text
success
failure
notApplied
reportOnly
```

**Do not confuse:**

```text
notApplied ≠ failure
```

# 6. MFA Fatigue / Prompt Bombing

### Purpose

Find users receiving repeated MFA failures.

```spl
index="task-4" sourcetype="azure:aad:signin" (status.errorCode=50074 OR status.errorCode=50076 OR status.errorCode=500121)
| stats count as mfa_failures values(status.errorCode) as errorCodes values(status.failureReason) as failureReasons by userPrincipalName, ipAddress
| sort - mfa_failures
```

```text
ONE USER
   ↓
MANY MFA FAILURES

SHORT WINDOW
   ↓
POSSIBLE MFA FATIGUE
```

# 9. Backdoor Account / New User Creation

### Purpose

Detect accounts potentially created for persistence.

```spl

| eval initiator=coalesce('initiatedBy.user.userPrincipalName','initiatedBy.app.displayName')
```

# 12. OAuth Consent

### Purpose

Detect application consent and potential OAuth persistence.

```spl
index="main" sourcetype="azure:aad:audit" activityDisplayName="Consent to application"
| eval initiator=coalesce('initiatedBy.user.userPrincipalName','initiatedBy.app.displayName')
| eval appName='targetResources{}.displayName'
| eval permissionsGranted='targetResources{}.modifiedProperties{}.newValue'
| table _time, initiator, appName, permissionsGranted
| sort - _time
```

### Three questions

```text
WHO?
 ↓
initiator

WHICH APP?
 ↓
appName

WHAT PERMISSIONS?
 ↓
permissionsGranted
```

### High-risk permissions from the material

```text
Mail.Read.All
Mail.ReadWrite.All
Files.ReadWrite.All
RoleManagement.ReadWrite.Directory
Directory.ReadWrite.All
offline_access
```

The source identifies `Consent to application` as the relevant Audit Log activity.

# 14. Query Selection Cheat Sheet

|Situation|Run|
|---|---|
|Seeing lots of failed logins|**#1 Failed Sign-in Base Filter**|
|One IP hitting many users|**#2 Password Spray**|
|One IP repeatedly hitting one user|**#3 Brute Force**|
|User appears suspicious|**#4 Risky User**|
|Login was blocked by policy|**#5 Conditional Access**|
|User receives many MFA failures|**#6 MFA Fatigue**|
|Need normal login behavior|**#7 Successful Sign-ins**|
|Investigating one specific account|**#8 User Timeline**|
|Suspect persistence via new account|**#9 Add User**|
|Suspect privilege escalation|**#10 Add Member to Role**|
|Suspect attacker-added MFA|**#11 Security Info Registration**|
|Suspect application persistence|**#12 OAuth Consent**|

# 15. Splunk Functions You Need to Know

### `stats`

Aggregate events.

```spl
| stats count by ipAddress
```

### `dc()`

Count unique values.

```spl
| stats dc(userPrincipalName)
```

**dc = distinct count**

### `count`

Count events.

```spl
| stats count as failures
```

### `by`

Group results.

```spl
| stats count by ipAddress
```

### `where`

Filter after processing.

```spl
| where policy_result="failure"
```

### `search`

Filter/search events.

```spl
| search userPrincipalName="user@company.com"
```

### `table`

Choose fields to display.

```spl
| table _time, userPrincipalName, ipAddress
```

### `sort`

Sort results.

```spl
| sort - _time
```

### `spath`

Extract nested JSON fields.

```spl
| spath
```

### `mvexpand`

Expand multivalue fields.

```spl
| mvexpand policies
```

### `eval`

Create/modify fields.

```spl
| eval initiator=...
```

### `coalesce`

Use the first available value.

```spl
| eval initiator=coalesce(field1, field2)
```

### `mvjoin`

Turn multivalue data into readable text.

```spl
| eval FailedPolicies=mvjoin(FailedPolicies, ", ")
```

# 16. Final Interview Cheat Sheet

### Password Spray

> **One IP → many accounts → failed authentication**

### Brute Force

> **One IP → one account → repeated failures**

### MFA Fatigue

> **One user → many MFA failures → eventual success**

### Risky User

> **Identity Protection considers the account risky**

### Conditional Access

> **Policy determines whether access is allowed, challenged, or blocked**

### Audit Logs

> **Tell me what happened after authentication**

### Privilege Escalation

> **Add member to role**

### Persistence — New Account

> **Add user**

### Persistence — MFA

> **User started security info registration**

> **Consent to application**
