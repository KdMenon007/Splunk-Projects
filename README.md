## 🧭 Project Methodology

The projects follow a practical learning workflow:

1. **Understand** — Learn the relevant security concepts and objectives.
2. **Configure** — Set up the lab, data sources, and required tools.
3. **Collect** — Ingest and inspect relevant security events.
4. **Investigate** — Use SPL and other appropriate techniques to examine activity.
5. **Analyze** — Interpret the results and consider alternative explanations.
6. **Document** — Record queries, observations, evidence, limitations, and lessons learned.
7. **Validate** — Test configurations and conclusions against actual lab results.

Where available, project folders contain:

Screenshots and sample results should be interpreted in the context of the captured lab session. They are not automatically proof of a successful detection or confirmed security incident.

---

## 🔐 Responsible Use

This repository is intended for educational and defensive cybersecurity learning.

- Use authorized lab environments and data.
- Do not publish credentials, tokens, private information, or sensitive organizational data.
- Validate searches against the actual indexes, sourcetypes, and fields in use.
- Distinguish suspicious indicators from confirmed malicious activity.
- Document limitations and avoid claiming results that have not been verified.
