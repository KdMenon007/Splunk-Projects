```text
AD Monitoring
│
├── Kerberos
│   ├── 4768 → TGT request
│   ├── 4769 → TGS request
│   └── 4771 → Kerberos pre-auth failure
│
├── NTLM
│   ├── 4776 → Credential validation
│   └── 4624 → Successful logon
│
├── Account Management
│   ├── 4720 → Account created
│   ├── 4722 → Account enabled
│   ├── 4724 → Password reset attempted
│   ├── 4725 → Account disabled
│   └── 4740 → Account locked
│
├── Group Management
│   ├── 4728 → Global group member added
│   ├── 4732 → Local group member added
│   └── 4756 → Universal group member added
│
├── Directory Service
│   └── 5136 → AD object/attribute modified
│
└── Logon
    ├── 4624 → Successful logon
    └── 4625 → Failed logon
```

# 2. AD Protocols

|Protocol|Ports|Purpose|
|---|---|---|
|**Kerberos**|`88`|Authentication, TGT/TGS|
|**LDAP**|`389`|Directory queries/modifications|
|**LDAPS**|`636`|Secure LDAP|

|**NetBIOS/SMB Legacy**|`139`|Legacy file sharing|
|**RDP**|`3389`|Remote Desktop|
|**NetBIOS Name Service**|`137`|Legacy name resolution|
|**NetBIOS Datagram**|`138`|Legacy network services|
|**LLMNR**|`5355`|Fallback name resolution|

### 🧠 Priority for SOC

```text
88   → Kerberos
389  → LDAP
445  → SMB
3389 → RDP
```

# 4. Kerberos Authentication

Kerberos uses tickets rather than sending the user's password across the network.

```text
User
 ↓
TGT Request
 ↓
DC
 ↓
TGT
 ↓
TGS Request
 ↓
Service
 ↓
Session
```

### Events

|Step|Event|Location|
|---|--:|---|
|TGT request|**4768**|Domain Controller|
|TGS request|**4769**|Domain Controller|
|Successful session|**4624**|Target server|
|Pre-authentication failure|**4771**|Domain Controller|

### 🧠 Memory

> **4768 = TGT**  
> **4769 = TGS**  
> **4624 = Logon**  
> **4771 = Kerberos pre-auth failure**

---

# 5. Kerberos Encryption Types

|Value|Algorithm|Typical Context|
|---|---|---|
|`0x12`|**AES-256**|Modern environments|
|`0x17`|**RC4-HMAC**|Legacy / older compatibility|

### Detection relevance

```text
0x12
→ Normal modern AES

0x17
→ Investigate context
```

⚠️ RC4 isn't automatically malicious.

It becomes particularly interesting when combined with:

```text
4769
+
0x17
+
Multiple SPNs
+
Short time period
```

→ Possible **Kerberoasting**

# 7. NTLM Authentication

NTLM is a legacy authentication protocol.

Common situations:

- Kerberos unavailable.
    
- Accessing resources by IP address.
    
- Legacy applications.
    
- Non-domain systems.
    
- Certain cross-domain scenarios.
    

```text
Target Server
     ↓
Requests credential validation
     ↓
Domain Controller
     ↓
4776
     ↓
Validation result
```

Then:

```text
Target
 ↓
4624
 ↓
Session
```

# 9. High NTLM Volume

Normally:

```text
Kerberos
>
NTLM
```

If you suddenly see large amounts of:

```text
4776
```

investigate:

- Legacy systems.
    
- Applications using IP addresses.
    
- Misconfigured DNS.
    
- Legacy authentication.
    
- Possible credential abuse.
    

### SOC mindset

> **High volume doesn't automatically mean attack. It means investigate why the environment is using NTLM so heavily.**

# 14. Event 5136 — Directory Service Changes

**5136 = AD object/attribute modification**

Unlike group membership events, 5136 can show the **specific LDAP attribute that changed**.

Important attributes:

|Attribute|What It Can Indicate|
|---|---|
|`userAccountControl`|Account/security setting changes|
|`servicePrincipalName`|SPN modification|
|`scriptPath`|Logon script modification|
|`member`|Group membership attribute changes|
|`displayName`|User information change|
|`description`|User information change|
|`title`|User information change|

### 🧠 Important

```text
4728
→ "Someone was added to a group"

5136
→ "Which AD attribute changed?"
```

# 15. GPO Monitoring — Event 5136

GPO modifications are particularly important because one GPO can affect many machines.

Potential attacker objectives:

```text
GPO modification
      ↓
Security configuration change
      ↓
Many machines affected
```

Possible impact:

- Disable security controls.
    
- Deploy malicious software.
    
- Establish persistence.
    
- Modify security policies.
    
- Affect large numbers of machines.
    

### Splunk

```spl
index=* EventCode=5136 Class="groupPolicyContainer"
| table _time, Subject_Account_Name, DN, LDAP_Display_Name, Value
| sort - _time
```

### Important fields

```text
Subject_Account_Name
→ Who modified it

DN
→ Which GPO

LDAP_Display_Name
→ Attribute modified

Value
→ New value
```

---

# 16. GPO Detection Caveat

Event 5136 captures **GPO object metadata changes** in AD.

It does **not necessarily tell you the exact policy setting that changed**.

For example:

```text
5136
→ versionNumber changed
```

doesn't necessarily mean:

```text
"Password policy changed from X to Y"
```

The actual policy configuration can reside in:

```text
SYSVOL
```

### SOC lesson

> **AD metadata monitoring and SYSVOL/policy-content monitoring are different visibility layers.**

# 22. Volume Is Normal

Large AD environments generate huge numbers of events.

Example rough daily volume for ~500 users:

|Event|Approx. Daily Volume|
|--:|--:|
|**4769**|50,000–100,000+|
|**4768**|5,000–10,000+|

### Key lesson

> **High event volume ≠ attack.**

Your job is to find the **anomaly inside the volume**.

# 23. Computer Accounts `$`

Computer accounts normally end with:

```text
$
```

Examples:

```text
THM-DC$
THM-IT-DESK$
SERVER01$
```

They generate large amounts of normal authentication traffic.

### Why?

- Machine-to-machine communication.
    
- System updates.
    
- Services.
    
- Automated processes.
    
- Domain operations.
    

---

# 24. Filter Computer Accounts

For human-focused investigations:

```spl
NOT Account_Name="*$*"
```

or:

```spl
Account_Name!="*$"
```

### Important

Don't permanently assume:

```text
$ = safe
```

Machine accounts can also be compromised.

Use filtering to **reduce noise**, not to declare something safe.

---

# 25. Compare Computer vs User Accounts

```spl
index=* EventCode IN (4624, 4768, 4769)
| eval AccountType=if(like(Account_Name, "%$%"), "Computer Account", "User Account")
| stats count by AccountType, EventCode
| sort AccountType, -count
```

### Purpose

Understand:

```text
Computer traffic
vs
Human traffic
```

Context matters.

|Activity|Expected Time|
|---|---|
|User logins|Business hours|
|Backup accounts|Overnight|
|Batch jobs|Scheduled windows|
|Admin activity|Maintenance windows|

### Example anomaly

```text
Admin account
+
3:00 AM
+
New workstation
+
Successful logon
```

```text
Backup account
+
2:00 AM
+
Known backup server
```

# 🎯 37. SOC Investigation Framework

For any AD alert:

```text
WHO?
→ Account

WHAT?
→ Event / action

WHEN?
→ Timestamp

WHERE?
→ Source IP / host

HOW?
→ Protocol / logon type / encryption

HOW OFTEN?
→ Volume / frequency

IS IT NORMAL?
→ Baseline

IS IT PRIVILEGED?
→ Account/group privileges

WHAT CHANGED?
→ Account / group / AD attribute

WHAT HAPPENED BEFORE?
→ Initial access / credential activity

WHAT HAPPENED AFTER?
→ Lateral movement / persistence
```
