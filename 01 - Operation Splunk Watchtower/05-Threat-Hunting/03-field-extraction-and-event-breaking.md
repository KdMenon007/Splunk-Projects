# Field Extraction and Event Breaking — Lab Notes\n\n## Example event shown in screenshots\n```text\n[Network-log]: User named Emily Clark from IT department accessed the resource Cybertees.THM/login.html from the source IP 10.0.0.5 and country Mexico at: Mon Oct 19 05:05:49 2026\n```\nVisible field names include `Username`, `Department`, `Domain`, `URI`, `SourceIP`, and `Country`.\n\n## Starting regex example\n```regex\nUser named (?<Username>.+?) from (?<Department>.+?) department accessed the resource (?<Domain>[^/\\s]+?)/(?<URI>\\S+?) from the source IP (?<SourceIP>\\d{1,3}(?:\\.\\d{1,3}){3}) and country (?<Country>.+?) at:\n```\nThis is a starting point, not a guaranteed match for every event variant. Test against multiple raw events and adjust for punctuation, URI formats, and line endings.\n\n## Event breaking shown in screenshot\n```ini\n[network_logs]\nSHOULD_LINEMERGE = true\nBREAK_ONLY_BEFORE = \\[Network-log\\]\n```\nWith line merging enabled, a new event begins when a line matches the marker. Use only if that marker reliably begins each event.\n\n## Validation\n1. Select the correct source type and representative sample.\n2. Test regex against multiple event variations.\n3. Verify extracted fields in search results.\n4. Validate event boundaries and timestamps.\n5. Save only after successful validation.\n6. Test parsing changes in a lab and follow the environment's deployment/restart process.\n\nParsing/event-boundary settings should be scoped to the actual sourcetype. Changes generally affect newly ingested events, not historical indexed events.\n
